## 1. 最重要的新核对：相同“100轮”不代表同等重复训练

| 到20k，每个训练seed | C固定两起点 | T轮换起点 |
| --- | ---: | ---: |
| 示范数 | 1600 | 1600 |
| 不同的示范—起点j | 3200 | 155832 |
| 起点被选中的总次数 | 320000 | 320000 |
| 每个起点平均被选中 | 100次 | 约2.05次 |
| 每次选择的clean训练行 | 2行 | 2行 |
| 每个起点平均训练行曝光 | 200行 | 约4.11行 |

精确分布是：T中151664个起点到20k被选中2次，4168个起点被选中4次。后者来自较短轨迹的分层支持提前耗尽。这里的一个epoch只遍历3200个逻辑slot；T每轮把slot映射到新j，并不在一轮中遍历15.58万个独特起点。T的前50轮总共接近遍历一次选定的起点集合，后50轮再次经过该集合；C则每轮都重新经过相同3200个起点。

这使“虽然都训练100轮，T应该已经和C一样拟合充分”的推断不成立。但不能反向写成“每点必须100次”：邻近起点的10步动作片段会重叠，模型可跨样本共享知识，且起点是已预训练/微调的π0.5-LIBERO，并非从零训练。统计单位是示范—起点，不是独立示范，也不是每个动作坐标只见过两次。

## 2. 正确恢复与适合T的优化日程是两个问题

完整恢复optimizer、EMA、RNG、global step和数据游标是正确且已核验的；本轮不质疑恢复方式。

但训练日程是否足以优化扩大后的数据支持，是另外一件事。实际日志确认：10k之后两个T seed每一步的学习率均为约2.5e−6，只有峰值2.5e−5的十分之一。与此同时，T到10k才走完首个50轮排程。更广的数据支持大多只在第一次经过时使用衰减中的学习率，第二次经过已经全部处在下限。

因此，平台可以是当前较低学习率下进展有限，而不等于已经抵达可达到的最优。它也可能与数据条件的难度、参数冻结范围、随机目标或拟合/泛化权衡有关。现有单条日程不能区分这些解释。

末1000步的实际记录如下。均值与中位数都保留，不能把图中的中位数当成全部batch平均loss。

| 19001–20000步 | C seed0 | C seed1 | T seed0 | T seed1 |
| --- | ---: | ---: | ---: | ---: |
| 训练loss均值 | 0.001942 | 0.001916 | 0.011465 | 0.011400 |
| 训练loss中位数 | 0.001240 | 0.001305 | 0.011077 | 0.010978 |
| 裁剪前梯度范数均值 | 0.04867 | 0.04675 | 0.06458 | 0.06207 |

后10k全部记录中，两T seed没有一个batch的loss低于0.001；梯度裁剪阈值1.0也从未触发。因此不能说图中约0.011只是少数尖峰拉高，或把平台归因为频繁裁剪。另一方面，随机batch梯度范数非零不是期望梯度非零的证明，也不是“未收敛”的充分证据；日志未保存实际参数更新范数，不能从名义学习率直接推出有效参数移动量。

## 3. 怎样看待0.001这个经验值

它可以成为需要检验的经验参照，尤其是来自同模型、同数据尺度、同loss定义的成功运行时。现在还没有把用户过去0.001对应的run与本批loss口径逐项对齐，因此不能把它直接升级为统一通过阈值，也不能声称这个经验无效。

本批loss是原生flow velocity残差，先在32个动作维上求均值，再在batch与10个动作位置上求均值；25个补零通道的flow目标仍参与计算。保持其它平均方式相同，精确有：

\[
L_{32}=\frac{7}{32}L_{7}+\frac{25}{32}L_{25}.
\]

因此，7维均值、32维均值、逐样本和逐维求和、online与EMA、随机增强与固定增强、flow时间采样不同，都可能使0.001含义不同。batch size本身不会给正确求均值的loss机械乘除一个系数，但会改变随机波动与优化轨迹。动作归一化、物理任务与可训练参数范围也要与经验来源对齐。

OpenPI官方实现明确采样noise与Beta时间，回归noise−actions，并返回动作维上的均方残差；本项目实际冻结源码已单独核对，当前main只作一手方法参考：[pi0.compute_loss](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0.py)。

更一般地，令Z=(输入条件,x_t,t)、U为随机flow目标，对当前数据分布的平方损失有回归分解：

\[
\mathbb E\|f_\theta(Z)-U\|^2
=\mathbb E\|f_\theta(Z)-\mathbb E[U\mid Z]\|^2
+\mathbb E\operatorname{tr}\operatorname{Cov}(U\mid Z).
\]

这解释了为什么随机条件flow训练目标的绝对值不能不加条件地当作生成误差或“学会”阈值。它与[Flow Matching原论文第3.2节、定理2](https://arxiv.org/html/2210.02747v2#S3.SS2)中CFM与边缘FM目标只相差参数无关项的结论一致。**本项目没有估计T的条件方差项；上式不能证明0.011是不可约下限，更不能用来免除继续检验欠优化。** 在有限确定性样本和足够可辨认条件下，该方差项可以很小，拟合到0.001可能完全可行。

C接近0.001而内部留出更差，只能反驳“低训练loss足以证明泛化好”；它不能反驳“充分训练T也许能更好”。同时，T从step0到10k的固定留出loss有改善，故“完全没有学习”不符合已有记录；更准确的问题是“T学得还不够，是否仍有可利用的优化余量”。

## 4. 哪些已有结论保留，哪些收紧

- 保留：在相同20k更新预算、同一内部demo留出监控上，T20任务均值低于C20，且四条件两seed的40任务都同向。这是当前训练方案的等预算结果。
- 保留：C在自身固定支持上训练loss下降、内部留出loss恶化。不能因此判T也不值得延长。
- 收紧：T在原日程后半段的内部监控近平台/略回升，只描述这一日程下的现象，不再作为“T已经训练到位”或“更充分优化没有价值”的证据。
- 尚未回答：同样训练到各自可达到的状态后C/T的比较；T能否达到0.001；在更充分拟合时，实际7维动作和Plus任务成功率是否改善。

目前缺少一个关键测量：同一组固定训练样本上、同一模型视图和配对随机性下的训练目标随checkpoint的变化。现有moving minibatch曲线并不是20k最终参数在全部T支持上的完整经验风险；内部EMA监控也不能补出它。

## 5. 下一项训练验证应直接检验优化充分性

以下是建议方案，未启动GPU或新的训练/模型调用，仍需在下一次明确执行范围中确定预算。

**先统一诊断口径。** 从已有训练支持按任务、示范和时刻分层固定一组train probe，覆盖C旧点和T新增点；继续使用独立demo内部验证，并保留不参与选择的行为确认集。固定一套augmentation/noise/t用于比较checkpoint，再用独立随机draw检验结论稳定性。分开报告online与EMA、全32维/实际7维/padding25维、执行前缀/完整H10以及flow时间段；不改训练目标来制造更小的loss。先复用已有10k/15k/20k checkpoint，不重训原模型。

**然后用同一个T20完整状态进行两条等预算接续。** 一条保留现有2.5e−6作为“单纯多训练”的对照；另一条只调整后续LR日程，保持原optimizer动量、EMA、RNG、输入顺序、数据支持、模型冻结范围和loss相同。可以先以相同的额外10k更新作有界检验，两个原训练seed分别比较；具体回升幅度和日程在查看已有数值稳定性后预先固定，不同时改数据或loss。原20k及原科学结局保留。资源不应从此前讨论自动扩张，原收尾最多8卡规则继续。

| 观察结果 | 可以作出的判断 |
| --- | --- |
| 原LR继续训练使固定train目标、留出及行为一起改善 | 支持原20k尚有有用的优化余量 |
| 仅调整LR分支显著推进固定train目标，并改善留出/行为 | 支持原日程限制了有效优化 |
| 固定train目标降到约0.001，留出或成功率未改善/变坏 | 更强拟合确实发生，但达到经验loss并不足以证明任务学好 |
| 两分支仍平台 | 不能直接宣布最优；再判断标签条件、容量/冻结范围或目标随机性，而非无止境加步 |

若连有限固定训练样本都拟合不下去，可用严格限于开发训练样本的小规模过拟合检查排除数据/目标/更新实现问题；它只说明有限样本可拟合性，不能替代真实训练与成功率。不要把这项诊断自动扩成新实验矩阵。

**建议调整的是科学优先级：应把“T是否欠优化”作为尚未解决、值得直接检验的问题，而不是用既有留出平台将其排除。0.001保留为待验证经验参照，最终判断同时看固定口径loss、留出表现和闭环成功率。**
